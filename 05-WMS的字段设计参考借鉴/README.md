## 字段表说明

每张表继续保留完整原始字段结构，并增加轻量化设计判断：

| 字段 | 说明 |
|---|---|
| 字段编码 | 保留数据字典原始编码，不因解释层统一术语而改名 |
| 字段名称 | 保留数据字典原始名称；原始错别字或错位通过风险块说明 |
| 字段类型 | 只做编码、名称、状态、数量、日期、规则、关联、描述、系统字段等粗粒度归类 |
| 数据类型/数据库属性 | 保留 `varchar(30)`、`char(1)`、`datetime`、`decimal(18,8)`、主键和原始备注 |
| 用途及后续使用 | 重点回答“在哪个页面/动作产生、被哪个节点读取、影响哪个对象/状态/数量” |
| 可用性 | 可直接采用、条件采用、暂不采用、待确认；表示通用或轻量化采用价值，不代表富勒当前是否启用 |
| 保留建议 | 必须保留、建议保留、可后置、可不纳入；不删除原始字典字段 |

对于不适合从资料确认的字段，使用“原文未说明/待确认”，不为了让模板完整而补写算法、外键或默认状态。

## 核心模块的深化方式

核心模块 `01—06` 和跨流程模块 `08、11、16—19` 在每章开头增加“表职责与字段联动”说明，使用以下六个问题检查核心表：

1. 表在业务链中是主数据、规则、单据、任务、库存结果、日志、报表还是临时/接口数据？
2. 哪个流程节点写入或更新它？是创建、执行、确认还是后台计算？
3. 哪些页面、任务、报表或接口会读取它？
4. 它改变的是状态、计划量、执行量、库存量、位置还是审计结果？
5. 取消、反向、重试或归档时，原记录怎么保留？
6. 哪些内容只是字段名或原始备注，不能据此推导技术实现？

关键字段再单独说明“来源字段 / 结果字段 / 配置字段 / 临时字段”的角色，避免所有字段都使用“后续在相关业务中使用”的模板句。

## 轻量化取舍原则

- 主数据、业务单据、库存数量、来源关联、关键状态和必要审计信息优先保留。
- 行业插件、自动化设备、复杂计费、RF 专属中间表、临时表和客户专属扩展字段通常条件采用或后置。
- 交易性字段优先写清来源动作、读取节点、结果影响和逆向边界；无法确认时标记待确认。
- 轻量化建议不会删除或改写数据字典中的字段，只说明实现时可以先不纳入。

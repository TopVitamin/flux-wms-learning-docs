# 富勒 WMS 产品设计精华知识借鉴

本目录不是富勒 WMS 用户手册的复述，而是以 1119 页版手册为事实基准，整理通用型 WMS 从 0 到 1 的产品设计方法、业务对象和模块设计。

当前基准为《富勒 WMS V6.2（最全版 1119 页）》：正式章节共 22 章；本目录另保留 3 个配置/计算实例作为补充材料，不将补充材料混入正式章节编号。

## 阅读方式

- `01-按章节拆分的md文件（1119页版本）` 是原始参考资料；本目录中的文档是基于参考资料形成的设计提炼。
- `02-按章节拆分的流程图` 是已有的 Mermaid 流程图配套资料，保留了较细的页面级流程和来源页码；本目录不重复搬运全部图，而是补充产品设计判断、对象、状态、字段和库存逻辑。
- 每个新版正式章节对应一个 Markdown 文档，文件编号与新版原章节保持一致；配置实例、计算实例统一放在“补充”文件中。
- 文档中的内容分为四种性质：
  - **参考事实**：富勒手册明确写出或展示的内容。
  - **归纳判断**：从多个页面或章节中整理出的产品设计规律。
  - **建议设计**：面向通用型 WMS 的设计建议，不代表富勒一定如此实现。
  - **待确认**：资料不足、存在多种合理方案，或需要结合目标业务确认的内容。

## 版本同步原则

- 新版 1119 页手册是本目录的当前事实基准，旧版 500 多页手册只用于识别增量，不再作为当前章节来源。
- 本目录只吸收会影响产品设计理解的增量：对象、流程、规则、状态、数据变化、权限、审计和系统边界；不复制全部页面文字和流程图。
- 手册没有说明的记账时点、算法、接口契约和状态回退，继续标记为“待确认”，不从页面名称推导结论。

## 设计主线

通用 WMS 设计不能只看菜单和页面，而要沿着下面的链路检查：

```text
基础资料/仓库结构
        ↓
业务规则与策略
        ↓
业务单据
        ↓
执行任务
        ↓
库存、容器、库位和流水
        ↓
查询、预警、报表、计费与追溯
```

核心业务模块的设计优先级通常是：

1. 基础资料、仓库结构和库存对象；
2. 入库、库存、出库主流程；
3. 规则、任务和异常处理；
4. 盘点、增值服务、计费和行业能力；
5. 报表、预警、打印、二次开发和运维能力。

## 条件性检查项

“库存影响”和“异常与逆向流程”不是每个模块的固定必填章节。

- 入库、上架、出库、拣货、补货、调拨、盘点、库存调整等交易性场景，必须分析。
- 基础资料、仓库配置、规则配置等场景，通常没有直接库存变化，但要分析停用、删除、引用和配置生效边界。
- 查询、报表、日志等只读场景，明确标记为“不适用”，不虚构库存操作。

判断优先以具体单据和操作为单位，而不是简单按照模块名称判断。

## 本目录采用的判断标准

每条“借鉴”都要回答五个问题，避免把富勒的页面和菜单直接当成通用产品答案：

| 判断维度 | 要回答的问题 | 输出方式 |
|---|---|---|
| 业务目的 | 这个功能服务哪个岗位、哪个仓储场景，解决什么问题 | 场景说明、业务结果 |
| 对象边界 | 它管理的是主数据、业务单据、执行任务，还是库存结果 | 实体表、单据关系 |
| 状态与动作 | 什么条件下能做什么，操作后谁的状态和数量发生变化 | 状态表、操作矩阵 |
| 规则与例外 | 默认路径是什么，哪些条件会分支，失败和取消怎么处理 | 流程图、异常/逆向表 |
| 可复用与取舍 | 哪些能力适合通用化，哪些属于行业或客户特例 | P0/P1/后续、待确认项 |

对交易型功能，还要追加两条判断：库存在哪个节点发生增加、减少、预占、冻结、释放或转移；异常发生后是取消、反向任务、反向库存事务，还是进入退货/调整流程。

## 每章的建议阅读顺序

先看“使用场景与业务价值”，再看业务流程；然后检查实体与单据关系，最后看字段、状态、库存影响和功能优先级。这样阅读出来的是一套可落地的设计，而不是一串菜单说明。

## 当前待确认问题

- 通用 WMS 首版是否支持多组织、多货主、多仓库，还是先收敛为单组织多仓库。
- 库存余额中的“可用、预占、冻结、待上架、待移出”等数量是否全部首版支持。
- PO、ASN、SO 是否都作为 WMS 内部单据维护，还是主要由 ERP/OMS 下达。
- 批次、序列号、容器和包装层级的首版边界。
- RF、自动化设备、TMS、ERP 等接口是否纳入首版。

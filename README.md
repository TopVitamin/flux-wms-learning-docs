# 富勒 WMS 拆解与产品设计参考

这是一套面向 WMS 学习、产品分析和字段建模的资料型项目。项目围绕富勒 WMS V6 用户手册和 FLUX WMS V431.114 数据字典，把原始资料拆成手册事实、流程图、原始数据、产品设计抽象和字段参考五个互相联动的层次。

项目名称沿用原始资料中的产品名称，但本仓库不是富勒官方文档，也不代表富勒产品的完整实现或当前版本行为。

## 这个项目解决什么问题

只看 WMS 手册，容易停留在菜单、按钮和页面截图；只看数据字典，又很难知道字段在哪个动作产生、被谁读取以及会影响什么结果。本项目把两类资料和产品设计思考接在一起，帮助读者沿着下面这条路径理解 WMS：

```text
原始资料 → 页面动作 → 业务对象与流程 → 数据表与字段 → 产品设计取舍
```

项目重点关注 PO、ASN、SO、Wave、Allocation、Task、Inventory、Transaction，以及入库、上架、库存、出库、任务、规则和逆向处理之间的关系。

## 适用于谁

| 读者 | 可以用它做什么 |
| --- | --- |
| WMS / 仓储产品经理 | 学习仓储业务对象、单据链、任务链和库存变化，辅助需求分析与产品设计 |
| 供应链产品经理和 ERP 产品经理 | 了解 WMS 与 ERP、OMS、TMS、RF、自动化设备之间可能的职责边界 |
| 实施顾问、业务顾问和仓库运营人员 | 按业务链回看页面动作、字段来源和异常处理，整理培训或调研材料 |
| 数据分析师、数据建模人员 | 从原始字段和流程结果反查表用途、字段角色和待确认关系 |
| AI 课程学习者、知识库建设者 | 练习如何把 PDF、Excel、流程图和解释层组织成可检索的业务资料 |

如果你需要的是可以直接部署的 WMS、官方 API 文档、数据库建表脚本或某个客户项目的实施方案，这个仓库不能直接替代它们。

## 这个项目是怎么做出来的

1. **确定事实边界。** 以用户手册作为业务事实源，以 Excel 作为原始数据字典；先规定“原文未说明”的内容不能写成确定结论。
2. **拆分手册。** 将 541 页 PDF 按正文实际章节拆成 23 个 Markdown 章节，并在正文中保留原 PDF 页码注释。
3. **整理流程图。** 从手册中的页面动作、按钮、分支和系统结果提取 Mermaid 图；每张图补充对应手册小节、PDF 页码和事实边界。
4. **转换数据字典。** 将 Excel 按原始模块整理成 Markdown，保留 331 张表的表名、字段编码、字段名称、数据库类型、主键和原始备注。
5. **建立业务语义层。** 集中整理 PO、ASN、SO、Wave、Allocation、Task、Inventory、Transaction 的对象关系、状态动作、库存数量和逆向处理。
6. **补充产品设计层。** 在 `04` 中区分手册事实、归纳判断、通用 WMS 建议和待确认内容，重点深化入库、库存、出库和任务主链。
7. **补充字段解释层。** 在 `05` 中把核心表连接到业务流程，说明字段产生动作、读取节点、结果影响和反向处理边界；不替换原始字段信息。
8. **做静态验收。** 检查 23 章覆盖、86 张图、331 张表、Markdown 链接、锚点、Mermaid 围栏和风险警示是否完整。
9. **进入 Git 版本管理。** 当前仓库已初始化为 `main` 分支，后续可以通过 commit 记录每轮资料修订。

## 事实、建议和风险怎么区分

在 `04` 和 `05` 中，引用块用于区分内容性质：

> **[手册事实]**：富勒手册明确写出或展示的页面、动作、参数或结果。
>
> **[归纳判断]**：从多个章节整理出的对象关系或设计规律，需要回看来源理解。
>
> **[通用 WMS 建议]**：面向通用产品的建议，不表示富勒一定采用该方案。
>
> **[待确认]**：手册、数据字典或当前整理结果不足以支持确定结论。

`03` 中发现的原始异常会保留原值并增加风险警示，例如：

- `DOC_Hold_Header` 与 `DOC_H0LD_Header` 的 `O/0` 差异；
- `ASNNo/ASNNO` 的描述出现 `ANS编号`；
- 个别表中的 `ADDWHO/ADDTIME`、`EditTime/EditWho` 疑似名称、描述或类型错位；
- `GroupBy` 描述中的 `GrouoMethod`；
- `SYS_ERROR_LOG` 的“系统伤心日志”等疑似整理问题。

这些内容没有被静默修正。使用前应回查原始 Excel、实际数据库对象或系统行为。

## 发布到 GitHub 前的注意事项

1. **先确认原始资料的公开权限。** `00-源文件/` 当前包含本地回查用的 PDF 和 Excel 原始附件，已被 `.gitignore` 排除，不会随本仓库提交。不要使用 `git add -f` 强行加入公开仓库；如果需要另行提供，应先确认相应的公开或再分发权限。
2. **本项目不是官方规格。** 不要依据这里的字段名、图示或产品建议直接生成生产数据库、接口契约、状态机或库存记账逻辑。
3. **`03` 是原始层。** 原始字段可能有错别字、命名差异或整理错误；解释层的 `ASN`、`模板`、`系统错误日志` 等规范写法不代表原始值已经被修订。
4. **图示需要回到来源。** Mermaid 图是对手册页面和动作的整理。遇到流程冲突时，以 `01` 的原文和 PDF 页码为准，并检查图下方的“事实边界”。
5. **Mermaid 渲染存在环境差异。** 本项目已做静态结构检查；当前整理环境没有 Mermaid CLI，因此没有把本地视觉渲染结果当作验收依据。建议在 GitHub 或其他支持 Mermaid 的 Markdown 渲染器中实际查看。
6. **当前没有单独的开源许可证。** GitHub 公开仓库不会自动授予原始 PDF、Excel、截图或其他第三方材料的版权和再分发权。若准备长期公开，建议先确认素材授权，并根据授权情况补充合适的 LICENSE。

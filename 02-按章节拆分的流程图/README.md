本目录目前覆盖第 1—23 章，来源文件为：

`../01-按章节拆分的md文件/`

目标读者是产品经理学习者。文档重点是帮助读者看懂业务主链、对象关系和关键判断，不复刻手册全部页面字段，也不把所有内容都画成图。

## 3. 核心章节的拆解策略

第 9—13 章是 WMS 的核心作业域，因此按“先理解，再操作，再处理分支”的顺序展开；第 14—23 章根据内容性质补充业务控制、配置链和结果追溯：

1. 业务层：先看主链或对象边界，回答“这类作业从哪里开始、到哪里结束”。
2. 操作层：展开菜单、按钮、页签和确认动作，回答“用户在页面上怎样完成这一步”。
3. 分支层：展开会改变库存、任务、单据状态或作业结果的判断，回答“系统为什么允许或不允许继续”。

字段清单和低影响的操作变体继续保留在来源 Markdown 中；但会影响作业结果的按钮、菜单和分支必须画出。重要逻辑只在最适合的一张图中展开，其他图通过文字引用其结果。

## 4. 图例与绘图规则

| 图形/连线 | 含义 |
|---|---|
| 普通矩形 | 作业动作、单据、库存结果或系统记录 |
| 菱形 | 原文明确存在的判断、配置开关或可选分支 |
| 实线箭头 | 原文明确描述的主流程、顺序或结果关系 |
| 虚线箭头 | 可选操作、辅助关系或原文没有规定为主链的关系 |
| 节点中的“原文未说明 / 待确认” | 资料不足，不能据此推导确定规则 |

绘图规则：

1. 粗略图只呈现主链路；中等图呈现关键分支、对象关系或系统层次；细图只展开确实影响理解的判断逻辑。
2. `flowchart` 用于流程、分支、层级和对象关系；`sequenceDiagram` 只用于明确存在角色交互和系统响应的场景。
3. 每张图都标注用途、原文依据、关键说明和事实边界。
4. 节点名称优先采用操作文档原词，不根据行业常识补充状态、字段、接口或业务动作。
5. 原文没有说明的内容，使用“原文未说明”或“待确认”标注，不绘制成确定分支。
6. 不把页面截图、字段清单和每个按钮都转换成图；只有当内容有助于理解主链、对象关系或关键判断时才保留。

## 5. 页码与事实追溯

每张图同时追溯到：

- 拆分后的来源 Markdown 文件；
- 原文章节和小节；
- 原 PDF 页码范围。

页码沿用原始 PDF 页码，不使用 Markdown 文件中的行号替代。图中的箭头只代表原文明确描述的顺序、归属、授权或优先关系；如果原文没有给出完整关系，文档会在“事实边界”中说明。
